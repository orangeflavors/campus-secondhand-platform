# 校园集市 · 系统实现说明

> 对应需求：SRS-CSTP-001 v1.1
> 实现范围：课程项目可运行版本（前后端、数据库、演示数据、接口测试）
> 相关文档：系统级说明见《系统说明》，环境依赖见《环境清单》。

## 1. 总体架构

```
┌──────────────────────────┐        HTTPS/JSON        ┌──────────────────────────┐
│  Vue 3 + Vite + TS 前端   │  ───────────────────────▶ │  Spring Boot 3 后端       │
│  Element Plus / Pinia     │   Authorization: Bearer   │  Controller → Service     │
│  Axios / Vue Router       │ ◀─────────────────────── │  → MyBatis Mapper         │
└──────────────────────────┘                          └────────────┬─────────────┘
                                                                   │ JDBC
                                                          ┌────────▼─────────┐
                                                          │    MySQL 8.0      │
                                                          │  16 张业务表       │
                                                          └──────────────────┘
```

- 前端为单页应用，Vite 开发服务器把 `/api` 与 `/uploads` 代理到后端 8080 端口。
- 后端无状态：JWT 携带用户标识，每个请求从数据库加载最新账户状态与认证状态。
- 所有业务数据落库，审计日志与通知独立记录。

## 2. 后端分层

| 层 | 说明 | 代表文件 |
|---|---|---|
| Controller | 参数校验、登录态与角色校验、统一响应 | `controller/ItemController.java` |
| Service | 业务规则、状态机、事务边界、权限细节 | `service/OrderService.java` |
| Mapper | MyBatis 接口 + XML，负责 SQL 与动态条件 | `mapper/ItemMapper.java`、`resources/mapper/*.xml` |
| Entity / VO / DTO | 数据实体、响应视图、请求体 | `entity/`、`vo/`、`dto/` |
| Security | JWT 解析、用户上下文、服务端鉴权工具 | `security/`、`config/SecurityConfig.java` |
| Common | 统一响应、错误码、异常处理、分页与文本工具 | `common/` |

业务异常统一抛出 `BizException`，由 `GlobalExceptionHandler` 转为 `{code, message}` 与对应 HTTP 状态；数据库唯一约束冲突转为 409，避免向前端泄露 SQL 细节。

## 3. 数据模型要点

| 表 | 作用 | 关键约束 |
|---|---|---|
| `sys_user` | 账户、认证、状态 | 用户名唯一、学号唯一 |
| `category` | 商品分类 | 编码唯一 |
| `item` / `item_image` | 商品与图片 | 卖家创建后不可更换；状态字段驱动生命周期 |
| `favorite` | 收藏 | `(user_id, item_id)` 唯一 |
| `conversation` / `message` | 咨询会话与消息 | `(item_id, buyer_id)` 唯一；仅双方可访问 |
| `trade_order` | 待确认请求 / 订单 | 生成列唯一索引：同商品最多 1 条活跃订单、同买家同商品最多 1 条待确认请求 |
| `handover_record` / `handover_log` | 交付约定与变更留痕 | 每订单 1 条当前记录，变更写日志 |
| `review` | 交易评价 | `(order_id, author_id)` 唯一，且服务端校验完成状态与 7 天窗口 |
| `report` | 举报 | 举报号唯一，保存对象快照 JSON |
| `moderation_action` | 处置动作 | 记录操作者、理由、依据与期限 |
| `audit_log` | 审计日志 | 仅追加，无删除接口 |
| `notification` | 站内通知 | 记录发送状态，失败可追踪 |

### 3.1 数据库层并发兜底

```sql
-- 同一商品最多 1 条已接受且未终结的订单
active_item_key BIGINT GENERATED ALWAYS AS (
  CASE WHEN status IN ('DELIVERING','BUYER_CONFIRMED','SELLER_CONFIRMED','DISPUTE')
       THEN item_id ELSE NULL END) STORED,
UNIQUE KEY uk_order_active_item (active_item_key)

-- 同一买家对同一商品最多 1 条待确认请求
pending_buyer_key VARCHAR(80) GENERATED ALWAYS AS (
  CASE WHEN status = 'PENDING_SELLER'
       THEN CONCAT(item_id, '-', buyer_id) ELSE NULL END) STORED,
UNIQUE KEY uk_order_pending_buyer (pending_buyer_key)
```

生成列为 `NULL` 时不参与唯一性判断，因此历史订单可以累积，而活跃订单与待确认请求天然唯一。

## 4. 核心状态机

### 4.1 商品

```
DRAFT ──提交──▶ PENDING ──批准──▶ ON_SALE ──接受请求──▶ LOCKED ──双方确认──▶ SOLD
  ▲                │                 │                    │
  │                └──驳回──▶ REJECTED                   └──取消/裁决关闭──▶ ON_SALE / OFF_SHELF
  └──────────── 修改 ◀─────────────┘

ON_SALE ──卖家下架──▶ OFF_SHELF
任意非终态 ──管理员违规下架──▶ VIOLATED
```

实现位置：`ItemService`（卖家操作、审核、下架）、`OrderService`（接受/取消/完成对商品状态的联动）。

### 4.2 订单

```
PENDING_SELLER ──接受──▶ DELIVERING ──买家确认──▶ BUYER_CONFIRMED ─┐
      │                     │                                    ├──双方均确认──▶ COMPLETED
      │                     └──卖家确认──▶ SELLER_CONFIRMED ─────┘
      ├──买家取消 / 卖家拒绝 / 超时 / 未中选──▶ CANCELLED
      └──取消（无人确认，商品恢复在售）

DELIVERING / BUYER_CONFIRMED / SELLER_CONFIRMED ──提交争议──▶ DISPUTE
DISPUTE ──管理员裁决──▶ COMPLETED / MANAGEMENT_CLOSED
```

- 接受请求与锁定商品在同一事务内完成；失败时整体回滚。
- 单方确认只写本方确认时间；双方确认后才完成订单并标记商品已售。
- 一方确认后普通取消返回 409，引导提交争议。

### 4.3 举报

```
SUBMITTED ──领取──▶ PROCESSING ──成立──▶ UPHELD ──申诉──▶ PENDING_APPEAL ──复核──▶ UPHELD / REJECTED
                        │         ├──不成立──▶ REJECTED
                        │         └──待补充──▶ SUPPLEMENT ──再处理──▶ PROCESSING
                        └──关闭──▶ CLOSED
```

举报成立时按对象类型自动执行处置：商品违规下架、用户警告/限权/封禁，并写入 `moderation_action` 与审计日志。

## 5. 权限与安全设计

| 场景 | 控制点 |
|---|---|
| 未登录访问 | Spring Security 过滤器链返回 401 JSON |
| 未认证浏览/交易 | `SecurityUtils.requireVerified()` → 403 `40301` |
| 限权/封禁 | `requireTradeable()` / `requireNotBanned()` → 403 `40302` |
| 越权访问他人商品/订单/会话/举报 | Service 内校验 owner / participant，失败返回 403 |
| 管理员接口 | `requireAdmin()`，前端路由守卫仅作体验优化 |
| SQL 注入 | MyBatis 预编译参数；关键词 LIKE 通配符转义（`ESCAPE '!'`） |
| XSS | 前端使用 Vue 文本插值，不渲染用户 HTML；后端对输入长度做约束 |
| 密码 | BCrypt 哈希存储，接口不返回密码字段 |
| 隐私 | 公开资料不返回学号、真实姓名、邮箱；联系方式按可见范围返回；统计接口不含个人明细 |
| 文件上传 | 仅图片类型、5MB 限制、UUID 文件名、路径规范化校验 |

## 6. 事务与并发

| 操作 | 事务与锁策略 |
|---|---|
| 创建待确认请求 | `SELECT ... FOR UPDATE` 锁定商品行，校验请求上限后插入 |
| 接受请求 | 固定顺序锁定商品行 → 订单行；校验商品在售、无活跃订单；更新订单、商品、其他请求 |
| 取消 / 拒绝 / 争议 | 锁定订单行后校验状态，再变更 |
| 确认交付 | 锁定商品行 → 订单行；单方确认或双方完成，商品与订单同事务更新 |
| 管理员裁决 | 锁定订单行，联动商品状态 |
| 举报处理 | 锁定举报行，处置与举报状态同事务 |
| 超时取消 | 定时任务每 60 秒扫描一次，逐条加锁处理 |

唯一索引作为最后一道防线：即使应用层判断出现竞态，数据库也会拒绝第二条活跃订单。

## 7. 通知与审计

### 7.1 通知

- `NotificationService.send(...)` 在事务提交后（`afterCommit`）通过独立事务写入，避免通知失败回滚核心业务。
- 写入失败时记录 `send_status = FAILED` 与重试次数，便于后续补偿。
- 覆盖：商品审核结果、新请求、接受/拒绝/未中选、取消、确认、完成、争议、评价、举报处理、账户处置。

### 7.2 审计

- `AuditService.log(action, targetType, targetId, reason, before, after)` 记录操作者、IP、时间与前后值。
- 覆盖：商品创建/编辑/提交/审核/下架/删除、订单创建/接受/拒绝/取消/确认/完成/争议/裁决/超时、举报创建/领取/处理/关闭/申诉、账户处置、校园认证与资料修改。
- 审计写入失败只记录错误日志，不影响业务结果；系统不提供审计删除接口。

## 8. 前端实现

### 8.1 结构

- `types/index.ts`：与后端 VO 一一对应的 TypeScript 类型，作为前后端契约。
- `utils/request.ts`：Axios 实例，自动附带 JWT、统一解包 `{code,message,data}`、401 跳转登录、错误提示去重。
- `stores/user.ts`：登录态、认证状态、账户状态与个人资料。
- `router/index.ts`：路由与守卫（登录、认证、管理员三类拦截）。
- `layouts/`：主站布局、个人中心布局、管理后台布局。
- `components/`：商品卡片、状态标签、订单卡片、风险提示、分页、空状态等通用组件。
- `views/`：市场、详情、发布/编辑、消息、订单详情、个人中心、管理后台等页面。
