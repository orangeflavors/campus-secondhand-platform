# 校园集市 · 前后端接口与页面说明

> 版本：v1.0（与 `database/schema.sql`、`frontend/src/types/index.ts` 同步）
> 用途：约束前端页面实现与后端接口行为，保证前后端契约一致。

---

## 1. 通用约定

### 1.1 响应包装

所有接口返回 JSON：

```json
{ "code": 0, "message": "ok", "data": {} }
```

- `code = 0` 表示成功，此时 `data` 为业务数据；失败时 `code` 非 0，`message` 为可直接展示的中文提示。
- HTTP 状态码同时表达语义：400 参数错误、401 未登录/登录失效、403 无权限/未认证/账户受限、404 资源不存在、409 状态冲突、500 服务异常。
- 前端 `src/utils/request.ts` 已统一处理：成功返回 `data`，失败自动 `ElMessage.error(message)`，因此页面中**不要重复弹错误提示**，只需处理 loading 与成功后的刷新。

### 1.2 认证

- 登录成功后前端保存 JWT，请求头 `Authorization: Bearer <token>`。
- 除 `/auth/login`、`/auth/register`、`/auth/password/reset`、`/api/meta/**` 外，其余接口均需登录。
- 浏览商品、发布、交易等操作还要求已完成校园认证（`authStatus = VERIFIED`）。
- 管理员接口要求 `role = ADMIN`。
- 登录失效（401）时前端自动清理 token 并跳转登录页。

### 1.3 分页

```json
{ "records": [], "total": 0, "page": 1, "size": 10 }
```

默认 `page = 1`，`size = 10`（商品搜索默认 12，最大 50）。

### 1.4 时间与金额

- 时间字段为 ISO 本地时间字符串，如 `"2026-10-15T12:30:00"`，前端用 `utils/format.ts` 的 `formatDateTime` 展示。
- 金额为数字（元），保留两位小数；`0` 表示免费流转，前端展示为「免费」。

### 1.5 账户与认证状态

| 字段 | 取值 | 说明 |
|---|---|---|
| role | USER / ADMIN | 管理员为平台运营人员，不参与普通交易 |
| authStatus | UNVERIFIED / PENDING / VERIFIED / REJECTED | 仅 VERIFIED 可浏览与交易 |
| accountStatus | NORMAL / LIMITED / BANNED | LIMITED 限制发布与下单，BANNED 禁止全部写操作 |
| contactVisibility | PUBLIC / AUTHENTICATED / PRIVATE | 控制联系方式对谁可见 |

### 1.6 错误码（业务提示文案由后端返回）

| code | 含义 |
|---|---|
| 40001 | 参数校验失败 |
| 40100 | 未登录或登录已失效 |
| 40301 | 需要完成校园认证 |
| 40302 | 账户受限（限权/封禁） |
| 40303 | 无权执行该操作 |
| 40401 | 资源不存在 |
| 40901 | 当前状态不允许该操作 |
| 50000 | 服务异常 |

## 2. 接口清单

> 请求体字段与 `frontend/src/types/index.ts` 中类型一致；下文只补充关键行为。
> 路径均以 `/api` 为前缀。

### 2.1 认证与用户

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/auth/register` | 注册；成功返回 `LoginResult`（自动登录），新用户 `authStatus = UNVERIFIED` |
| POST | `/auth/login` | 登录；返回 `LoginResult`；用户名或密码错误返回 401「用户名或密码错误」 |
| POST | `/auth/password/reset` | 模拟找回凭据：`username + studentNo + newPassword` 三者匹配才成功 |
| GET | `/auth/me` | 当前用户信息（含本人完整手机号、学号与统计） |
| PUT | `/users/me` | 修改昵称/学院/手机/邮箱/头像/联系方式可见范围 |
| POST | `/users/me/campus-auth` | 校园认证（模拟认证服务）：学号 8-12 位数字、姓名与学院必填；成功后 `VERIFIED` 并记录 `authMethod = STUDENT_NO`、`authTime` |
| GET | `/users/{id}/profile` | 他人公开资料：昵称、头像、学院、认证状态、评分、评价数、成交数、可见的联系方式 |
| GET | `/users/{id}/reviews` | 该用户收到的评价（分页），含评价人与订单信息 |

注册校验：用户名 4-20 位字母/数字/下划线且唯一；密码 6-32 位；昵称 2-20 字。

### 2.2 元数据

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/meta` | 一次性返回 `{ categories, conditions, areas, reportCategories }` |
| GET | `/meta/categories` | 分类列表 |

### 2.3 商品

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/items` | 搜索在售商品：`keyword`（标题/描述模糊，空关键词返回默认列表）、`categoryId`、`minPrice`、`maxPrice`、`condition`、`area`、`sort`（latest/price_asc/price_desc）、`page`、`size` |
| GET | `/items/{id}` | 商品详情；浏览量 +1；非在售商品仅本人/管理员可见（否则 404）。返回 `ItemDetailVO`，含 `canOrder`、`cannotOrderReason`、`isFavorite`、`isOwner`、`riskNotice` |
| POST | `/items` | 创建商品草稿（状态 DRAFT），需认证且账户可发布 |
| PUT | `/items/{id}` | 编辑商品；仅在 DRAFT/REJECTED/OFF_SHELF/ON_SALE 可编辑；对在售商品修改标题/分类/价格/描述/成色等关键字段会重新进入待审核（BR-04） |
| DELETE | `/items/{id}` | 仅本人，且仅 DRAFT/REJECTED/OFF_SHELF 且无订单时可删除 |
| POST | `/items/{id}/submit` | 提交审核；校验必填项与至少 1 张图片（BR-02），DRAFT/REJECTED/OFF_SHELF → PENDING |
| POST | `/items/{id}/off-shelf` | 卖家主动下架；仅 ON_SALE 且无活跃订单可下架 |
| GET | `/items/{id}/favorite` | 收藏状态 `{ favorited, count }` |
| POST | `/items/{id}/favorite` | 收藏（幂等） |
| DELETE | `/items/{id}/favorite` | 取消收藏（幂等） |
| GET | `/me/items` | 我的商品（含全部状态，分页，支持 `status` 筛选） |
| GET | `/me/favorites` | 我的收藏（分页，返回在售/已失效商品卡片） |

`canOrder = false` 的常见原因（`cannotOrderReason`）：商品非在售、不能购买自己发布的商品、账户被限权/封禁、你已有一条待卖家确认的请求、该商品待确认请求已达上限。

### 2.4 咨询

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/conversations` | `{ itemId }`：创建或返回当前买家与该商品的会话；不能与自己的商品会话 |
| GET | `/conversations` | 我的会话列表，按最近消息倒序 |
| GET | `/conversations/{id}` | 会话详情（仅双方） |
| GET | `/conversations/{id}/messages` | 消息列表，支持 `afterId` 增量拉取 |
| POST | `/conversations/{id}/messages` | 发送文字消息（1-1000 字）；封禁用户禁止发送 |

### 2.5 订单（待确认请求与交易）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/orders` | `{ itemId, remark? }` 创建待确认请求：商品须在售、非本人、本人无待确认请求、该商品待确认请求 < 10（BR-19）；成功返回 `OrderVO`，`expireAt = 当前时间 + 24 小时`（BR-07） |
| GET | `/orders` | 我的订单：`role=BUYER/SELLER`（缺省全部）、`status` 可选；按更新时间倒序返回 `OrderVO[]`（不分页） |
| GET | `/orders/{id}` | 订单详情（仅买卖双方或管理员） |
| POST | `/orders/{id}/accept` | 卖家接受：请求 → 待线下交付、商品 → 已锁定、同商品其他待确认请求 → 已取消（未中选）并通知；原子事务 + 行锁 |
| POST | `/orders/{id}/reject` | 卖家拒绝：`{ reason }`（2-200 字），请求 → 已取消（卖家拒绝） |
| POST | `/orders/{id}/cancel` | 取消：`{ reason }`。待卖家确认时买家可取消；待线下交付且无人确认时双方均可取消，商品恢复在售；一方已确认后拒绝普通取消（409） |
| PUT | `/orders/{id}/handover` | `{ handoverTime?, area?, note? }` 约定交付信息，记录变更留痕并通知对方 |
| POST | `/orders/{id}/confirm` | 确认交付：单方确认只更新本方字段；双方均确认后订单完成、商品已售（同一事务） |
| POST | `/orders/{id}/dispute` | 提交争议：`{ reason }`，进入争议中，商品保持锁定 |
| GET | `/orders/{id}/handover-logs` | 交付约定变更记录 |
| POST | `/orders/{id}/reviews` | `{ rating: 1-5, content }` 评价对方：仅已完成订单、每方一次、完成后 7 天内（BR-11） |
| GET | `/orders/{id}/reviews` | 该订单评价列表 |

`OrderVO.actions` 由服务端计算，前端只按布尔值显示按钮：
`canAccept / canReject / canCancel / canConfirm / canDispute / canReview / canEditHandover`。

订单状态：`PENDING_SELLER`（待卖家确认）→ `DELIVERING`（待线下交付）→ `BUYER_CONFIRMED` / `SELLER_CONFIRMED` → `COMPLETED`；
异常分支：`CANCELLED`、`DISPUTE`、`MANAGEMENT_CLOSED`。

### 2.6 举报与通知

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/reports` | 举报商品/用户/消息：`{ targetType, targetId, category, description }`；生成唯一举报号并保存对象快照（BR-12） |
| GET | `/reports/mine` | 我提交的举报（分页） |
| GET | `/reports/{id}` | 举报详情（举报人/管理员） |
| POST | `/reports/{id}/appeal` | 被处置方申诉：`{ reason }`，举报进入申诉中 |
| GET | `/notifications` | 我的通知（分页，`unread=true` 只看未读） |
| GET | `/notifications/unread-count` | 未读数量 |
| PUT | `/notifications/{id}/read` | 标记已读 |
| PUT | `/notifications/read-all` | 全部已读 |

举报类别：`PROHIBITED` 违禁物品、`FAKE` 虚假信息、`FRAUD` 欺诈行为、`ABUSE` 辱骂骚扰、`SPAM` 广告刷屏、`OTHER` 其他违规。

### 2.7 文件上传

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/files/upload` | `multipart/form-data`，字段名 `file`；仅图片（png/jpg/jpeg/webp/gif），≤5MB；返回 `{ url, name }`，`url` 形如 `/uploads/2026/10/xxx.png`，可直接用于商品图片 |

### 2.8 管理端

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/admin/items` | 商品审核列表：`status`（默认 PENDING）、`keyword`、分页；返回 `AdminItemVO` |
| POST | `/admin/items/{id}/approve` | 批准：PENDING → ON_SALE，记录审核人/时间并通知卖家 |
| POST | `/admin/items/{id}/reject` | 驳回：`{ reason }` 必填，PENDING → REJECTED 并通知卖家 |
| POST | `/admin/items/{id}/takedown` | 违规下架：`{ reason, ruleBasis? }`，商品 → VIOLATED；若存在活跃订单，订单转争议并通知双方 |
| GET | `/admin/reports` | 举报列表：`status`、分页；含举报人、对象摘要、状态 |
| POST | `/admin/reports/{id}/claim` | 领取：SUBMITTED → PROCESSING，记录处理人 |
| POST | `/admin/reports/{id}/handle` | 处理：`{ result: UPHELD/REJECTED/SUPPLEMENT, ruleBasis?, reason, actionType?, durationDays? }`；成立时自动执行处置（商品下架或用户警告/限权/封禁） |
| POST | `/admin/reports/{id}/close` | 关闭举报 |
| POST | `/admin/reports/{id}/appeal/resolve` | 申诉复核：`{ uphold, reason }` |
| GET | `/admin/orders` | 争议订单列表（`status=DISPUTE`），分页 |
| POST | `/admin/orders/{id}/resolve` | 裁决：`{ outcome: COMPLETE/CLOSE, reason }` |
| GET | `/admin/users` | 用户列表：`keyword`、`accountStatus`、`authStatus`、分页 |
| GET | `/admin/users/{id}` | 用户详情（含统计） |
| POST | `/admin/users/{id}/sanction` | 账户处置：`{ actionType: WARN/LIMIT/BAN/UNBAN, reason, ruleBasis?, durationDays? }` |
| GET | `/admin/users/{id}/actions` | 该用户历史处置记录 |
| GET | `/admin/stats` | 聚合统计：`from`、`to`（`yyyy-MM-dd`，默认近 30 天） |
| GET | `/admin/audit-logs` | 审计日志：`action`、分页 |

管理员所有处置动作均写入 `audit_log`，并通知相关用户。

## 3. 页面规格

> 所有页面使用 `<script setup lang="ts">` + Element Plus；样式与现有绿色主题一致（`--brand-*` 变量、圆角卡片）。
> API 错误已由拦截器统一提示，页面只处理成功回调与 loading。
> 空数据使用 `components/EmptyState.vue`；分页使用 `components/AppPagination.vue`。

### 3.1 登录 / 注册 / 找回（`views/LoginView.vue` 等）

- 左右分栏：左侧品牌介绍与平台规则要点，右侧表单卡片。
- 登录：用户名 + 密码；支持回车提交；成功跳转 `redirect` 参数或 `/`（管理员跳 `/admin/dashboard`）。
- 演示账号提示：`seller01 / 123456`（已认证卖家）、`buyer01 / 123456`（已认证买家）、`admin / admin123`（管理员）、`newbie01 / 123456`（未认证）。
- 注册：用户名、昵称、密码、确认密码、学院、手机号、学号（选填）；成功后自动登录并跳转 `/verify`。
- 找回：用户名 + 学号 + 新密码；提交成功后回登录页。

### 3.2 校园认证（`views/VerifyView.vue`）

- 说明认证用途与隐私边界；表单：学号（8-12 位数字）、真实姓名、学院。
- 已认证时展示认证信息与「已认证」状态；未认证提交后刷新用户信息并跳转 `redirect` 或首页。
- 严禁在页面展示他人学号或认证凭据。

### 3.3 市场首页（`views/MarketView.vue`）

- 顶部搜索区：关键词输入 + 搜索按钮；分类快捷筛选（全部 + 各分类）；更多筛选（价格区间、成色、交付区域、排序）。
- 搜索条件与 URL query 同步（`keyword/categoryId/sort` 至少支持），刷新后保持。
- 结果统计「共 N 件在售商品」；商品卡片网格（`ItemCard`）；加载骨架屏；无结果时 `EmptyState` 并提供「清除筛选」。
- 分页（每页 12）。

### 3.4 商品详情（`views/ItemDetailView.vue`）

- 左侧图片区（主图 + 缩略图切换，无图用占位图）；右侧信息：标题、价格（0 元显示免费）、状态标签、成色/分类/区域、卖家卡片（头像、昵称、学院、认证标识、星级与评价数）、操作按钮。
- 操作：收藏/取消收藏、咨询卖家、申请购买、举报。
- 申请购买弹窗：展示 `RiskNotice` 与备注输入；成功后跳转订单详情。
- `canOrder = false` 时按钮禁用并展示 `cannotOrderReason`。
- 本人查看时显示「编辑」「提交审核」「下架」等入口与驳回原因。
- 底部展示商品描述、卖家评价列表；举报弹窗（类别 + 说明）。

### 3.5 发布 / 编辑（`views/PublishView.vue`）

- 表单：标题、分类、成色、价格、交付区域、描述、图片（最多 6 张，本地上传或输入图片地址）。
- 校验：标题 2-100、分类必选、成色必选、价格 ≥ 0、区域必选、描述 ≥ 10 字、提交审核时至少 1 张图片。
- 按钮：「保存草稿」创建/更新为 DRAFT；「提交审核」保存后调用 submit；编辑已发布商品时提示关键字段修改将重新审核。
- 编辑模式加载现有数据；显示当前状态与驳回原因。

### 3.6 消息（`views/MessagesView.vue`）

- 左侧会话列表（商品缩略图、对方昵称、最后一条消息、时间），支持通过 `?conversation=id` 选中。
- 右侧聊天区：消息气泡（本方右侧、对方左侧）、时间、发送框（Enter 发送，Shift+Enter 换行）。
- 每 5 秒增量拉取新消息；发送后滚动到底部。

### 3.7 订单详情（`views/OrderDetailView.vue`）

- 顶部：订单号、状态标签、创建时间、时效提示（待确认请求显示剩余时间）。
- 商品摘要卡（跳转商品详情）、买卖双方信息、交付约定区（时间/区域/备注 + 修改按钮 + 双方确认时间）。
- 状态步骤条：提交请求 → 卖家接受 → 双方确认 → 完成（取消/争议显示对应提示）。
- 按 `actions` 显示按钮：接受、拒绝、取消、确认交付、提交争议、评价；所有危险操作需二次确认并填写原因。
- 展示双方评价、交付变更记录（可折叠）。

### 3.8 个人中心

- `me/ProfileView`：资料表单、账户状态提示、认证状态卡片（去认证）、个人统计（发布/成交/评价/评分）、收到的评价列表。
- `me/MyItemsView`：状态标签页（全部/草稿/待审核/在售/已锁定/已售出/已驳回/已下架/违规下架）+ 列表；操作：编辑、提交审核、下架、删除、查看；展示驳回原因。
- `me/FavoritesView`：收藏商品网格，支持取消收藏。
- `me/OrdersView`：Tab「我买到的 / 我卖出的」+ 状态筛选；订单卡片（`OrderCard`）与快捷操作。
- `me/ReportsView`：我提交的举报列表，状态、对象、处理结果；详情弹窗。
- `me/NotificationsView`：通知列表（未读高亮）、标记已读、全部已读、按关联对象跳转。

### 3.9 管理后台

- `admin/DashboardView`：时间范围筛选；指标卡（发布量、成交量、成交率、评价均分、举报总数、处置数）；趋势折线图（发布/成交）；举报状态饼图；分类分布表。
- `admin/ItemAuditView`：状态筛选与关键词；表格（封面、标题、卖家、价格、分类、提交时间、状态）；详情抽屉（描述、图片、卖家信息）；批准/驳回/违规下架。
- `admin/ReportManageView`：状态 Tab；表格；领取、处理（结论/规则依据/理由/处置动作）、关闭、申诉复核。
- `admin/DisputeOrdersView`：争议订单表格；裁决弹窗（完成订单 / 管理关闭 + 理由）。
- `admin/UserManageView`：筛选与列表；详情抽屉（资料、统计、处置历史）；处置弹窗（警告/限权/封禁/解封 + 理由 + 时长）。
- `admin/AuditLogView`：审计日志表格（时间、操作人、动作、对象、理由、前后值），按动作筛选，分页。

## 5. 前端实现约束

1. 不修改 `src/types`、`src/api`、`src/utils`、`src/components`、`src/layouts`、`src/router` 中的既有契约；如确需新字段，先在后端与类型文件同步并由负责人确认。
2. 所有页面必须处理：加载中、空数据、接口失败（拦截器已提示，页面保持原状）。
3. 使用 `ElMessage` 做操作成功提示；危险操作使用 `ElMessageBox.confirm`。
4. 不引入新依赖（图表使用已安装的 `echarts`）。
5. 所有页面自适应：≤768px 时布局纵向堆叠，表格可横向滚动。
6. 金额、时间、状态一律通过 `utils/format.ts`、`utils/dict.ts`、`StatusTag.vue` 统一展示。
