### P0-02（补充证据）原型实现与 SC-04/PV-05 直接冲突

原型 `index.html` 第 139 行 `buy(id)`：

```js
const existing=orders.find(o=>o.itemId===id&&!['已取消','已完成','管理关闭'].includes(o.status));
if(existing)return notify('该商品已有活跃订单（BR-06）');
```

这行代码把“待卖家确认”也算作活跃订单：只要存在一条未取消/未完成/未管理关闭的订单，就不能再创建第二条。于是：

- SC-04 的初始状态“订单 O-A、O-B 均待卖家确认”无法在原型中构造。
- PV-05 的“创建两个待确认订单并依次接受”无法执行。
- 原型第 147 行 `orderAction('accept')` 还会检查“其他活跃订单”，与 `buy()` 一起把“单活跃订单”锁死为“单待确认订单”。

这说明团队在原型层已经选择了“一个待确认订单”的实现，而 SRS/SC-04/PV-05 仍写“多待确认订单、卖家选择”。两者只能保留一个：

- 若保留卖家选择：`buy()` 必须允许同一商品多条“待确认请求”，`accept()` 时再做唯一锁定，SC-04/PV-05 才成立。
- 若保留“先到先得”：删除 SC-04/PV-05 的多订单场景，重写 US-07/FR-018/AC-05。
