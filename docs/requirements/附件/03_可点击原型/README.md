# 可点击原型说明

> 原型版本：v1.1（C-01 修订）  
> 文件：`index.html`  
> 使用方式：双击文件，用 Chrome/Edge 等现代浏览器打开。无需服务器或安装依赖。

## 1. 原型覆盖

- 买家（林同学/李同学）/卖家/未认证用户/管理员身份切换；
- 商品搜索、分类与成色筛选、价格排序；
- 收藏、详情咨询、创建待确认请求和举报；
- 商品发布、待审核、批准/驳回；
- 卖家接受/拒绝订单；
- 订单取消、双方交付确认、完成、评价和争议；
- 管理员举报处理、商品违规下架和内存审计事件；
- 商品、订单、举报聚合统计。

## 2. 明确限制

这是需求走查原型，不是生产系统：

- 数据只存在浏览器内存，刷新或点击“重置演示数据”会复位；
- 校园认证、图片上传、内容审核、通知和封禁只做界面模拟；
- 没有数据库、服务端权限、真实并发、事务、加密或不可篡改审计；
- 单浏览器交互不能验证 PV-05b 的并发唯一性；PV-05a 的顺序规则可在原型验证。
- 页面流程通过不能写成“功能验证通过”。

## 3. 推荐走查顺序

1. PV-01：保持“买家”，搜索“教材”，筛选“教材资料”，收藏 I-001。
2. PV-02：切换“卖家”，发布新商品；切换“管理员”，在审核队列批准；切换“买家”，确认商品进入列表。
3. PV-03：买家对 I-001 创建待确认请求；切换卖家接受；卖家先确认；切换买家再次确认；检查订单完成、商品退出在售列表。
4. PV-04：重置后切换“未认证用户”，尝试发布或创建待确认请求，检查拒绝提示和状态不变。
5. PV-05a：买家林同学创建待确认请求；切换买家李同学创建第二个请求；切换卖家接受林同学的请求；确认李同学请求自动取消（未中选）；再尝试接受李同学请求应失败。PV-05b：真正并发接受仍需后端测试。
6. PV-06：创建并接受订单，一方确认后点击普通取消，检查系统拒绝；再提交争议。
7. PV-07：买家举报某商品；管理员处理为成立，检查商品违规下架及审计事件。
